## Explicit eligibility and historical qualifications

- F16 KlikQRIS: Current source/provider-switch policy and codebase instructions prohibit new target/fallback creation; preserve historical reads/recovery. A historical checkout test is not activation authority.
- F18 Pakasir: historical callback/reconciliation/retirement only; no new funding target.
- F24 USDT/BSC funding: implemented code is **unqualified** absent operator custody/legal/provenance/treasury evidence. ADR-0027 shared receiver eligibility does not waive release gates. Legacy exclusive receiver history remains.
- F37 automatic pins: **retired**, not unknown/new work. ADR-0031's old pin scenarios are historical and must not become acceptance requirements for automatic pinning.
- F10–F12 supplier support: ADR-0017 explicitly retires provider-specific warranty claim workflows; preserve historical entitlement and local remedies rather than reviving retired provider APIs. retired adapters/purchase modes may still own historical entitlement, warranty/refund and serialized job obligations. Snapshot/operator evidence is needed to enumerate actual historical rows, not permission to erase source paths.
- ADR-0019 remains Proposed as a decision document; its implemented child seams have source evidence but the proposal itself does not authorize new financial capabilities. ADR-0013/0015 icon history must be read with current family-owned ADR-0024. ADR-0030's receipt isolation remains current after pin retirement.

No activation, UI redesign, provider fallback, funding enablement or business scope reduction is authorized by this matrix.

ADR conflict: ADR-0006 still describes KlikQRIS as selectable/new-use eligible, whereas current `PaymentProviderSwitcher::assertReady` rejects retired providers and the implementation map prohibits new KlikQRIS targets. Preserve the current historical-only behavior; G13 tracks the stale decision text rather than treating it as activation permission.
