# Akunding Store Reseller API v1 — verified contract

Research is based only on Akunding's first-party API reference, read 2026-11-14. No authenticated request was made. Examples below are descriptive; no credentials are included.

Primary source: [Reseller API v1 reference](https://akunding.shop/api/docs). The reference links the machine-readable [OpenAPI document](https://akunding.shop/api/openapi.json), while explicitly warning that its schema incorrectly marks the idempotency header optional; this report treats the human reference as authoritative. Relevant section links are given inline.

## Documented contract

- **Base and transport:** `https://akunding.shop/api`; HTTPS, JSON. Monetary values are USDT; timestamps are Unix seconds UTC. ([intro](https://akunding.shop/api/docs#content))
- **Authentication:** every endpoint uses `Authorization: Bearer <API key>`; no cookies or other tokens. Missing/invalid key returns 401; blocked account 403. ([Authentication](https://akunding.shop/api/docs#authentication))
- **Balance:** `GET /v1/me` returns account identifiers/names plus `balance`, `referral_credit`, `paid_balance`, and `api_key_prefix`. Balance is spendable USDT rounded to 2 decimals; credit and paid balance up to 4 decimals. ([GET /v1/me](https://akunding.shop/api/docs#get-me), [Balance and pricing](https://akunding.shop/api/docs#balance))
- **Catalog:** `GET /v1/products` returns an array; optional `include_out_of_stock=true` includes sold-out items (stock zero, unavailable), but hidden products remain excluded. `GET /v1/products/{product_id}` returns one product, including sold-out products. Product fields: `id`, `name`, `description`, `features`, `unit_label`, `base_price`, `your_price`, `has_special_price`, `stock`, `available`, `bulk_tiers` (`min_qty`, `unit_price`, `your_unit_price`). Prices are per-unit USDT. `your_price` is the account's special price if applicable; server selects the lower of that or applicable bulk tier. ([GET products](https://akunding.shop/api/docs#list-products), [GET product](https://akunding.shop/api/docs#get-product), [product object](https://akunding.shop/api/docs#product-object), [pricing](https://akunding.shop/api/docs#balance))
- **Create order:** `POST /v1/orders`; required bearer auth, `X-Idempotency-Key` (1–120 chars), and `Content-Type: application/json`. JSON body: integer `product_id`, integer `quantity` 1–1000. Success is 200 order object plus `charged` (wallet amount) and `idempotent` boolean. A repeated key/request returns prior order without double charge. ([POST orders](https://akunding.shop/api/docs#create-order), [idempotency](https://akunding.shop/api/docs#idempotency))
- **Order lookup/status:** `GET /v1/orders/{order_id}` returns an order including `items` (empty until delivery). `GET /v1/orders` lists newest first, without items, at most latest 100, no pagination; `limit` optional 1–100, default 50. ([GET orders](https://akunding.shop/api/docs#list-orders), [GET order](https://akunding.shop/api/docs#get-order))
- **Order fields:** `id`, `status`, `product` (`id`,`name`,`unit_label`), `quantity`, `unit_price`, `subtotal`, `discount`, `payable`, `payment_method`, `created_at`, `delivered_at`; single-order responses additionally include `items`, one string per unit (code/account). POST adds `charged`, `idempotent`. ([order object](https://akunding.shop/api/docs#order-object))
- **Statuses:** API order statuses are `delivered`, `paid`, `failed`, `draft`. `delivered` includes items; `paid` means payment taken, delivery pending, items empty; poll the same order every 10 seconds or repeat the same POST/key, never purchase again. `failed` means no delivery and refund to wallet. `draft` means unpaid/not charged; retry same key after topping up/restocking or abandon. Account history may also contain bot statuses `awaiting_payment`, `expired`, `cancelled`, `preorder_paid`. ([orders and delivery](https://akunding.shop/api/docs#delivery))
- **Cancel:** no cancellation endpoint is documented in the reference. `cancelled` is mentioned only as a possible status for bot orders in account history. ([orders and delivery](https://akunding.shop/api/docs#delivery), [endpoint reference](https://akunding.shop/api/docs))
- **Idempotency:** required per order; reuse same key for retry of same purchase, new unique key for a different purchase. Reuse with different product/quantity is 409. Key max length 120; absent/blank/too long is 400. A paid/delivered/failed/expired key remains tied to that order. An unpaid attempt can be retried after top-up; quoted price retained for 60 minutes, then current price applies; after 7 days the unpaid attempt is deleted and key released. A failed/expired order key is no longer payable (409). ([Idempotency keys](https://akunding.shop/api/docs#idempotency))
- **Errors:** JSON errors generally have `detail`; 402 detail is an object (`message`, `balance`, `payable`, `short`), 422 is a list of field problems. Important documented codes: 400 invalid/missing idempotency; 401 auth; 402 insufficient balance; 403 blocked; 404 product/order absent or unavailable; 409 stock/idempotency/order-state conflicts; 422 invalid input; 429 rate limited; 5xx transient proxy/server errors may be HTML. ([Errors](https://akunding.shop/api/docs#errors), [Balance](https://akunding.shop/api/docs#balance))
- **Rate limits/retries:** per API key burst of 150 then 15 requests/second; 429 includes `Retry-After`. Per-IP limit has bursts of about 50 and may return HTML 429 without `Retry-After`; docs say wait 1 second. Docs recommend refreshing catalog every 1–5 minutes; stock can change between listing and ordering. Their sample purchase flow retries network errors and 5xx with exponential backoff, 429 after `Retry-After`, always same idempotency key; 402 after top-up also same key. Poll pending delivery every 10 seconds. ([Rate limits](https://akunding.shop/api/docs#rate-limits), [production purchase example](https://akunding.shop/api/docs#quick-start))

## Not documented / boundaries

- No cancellation API or semantics for cancelling API-created orders are specified.
- No catalog pagination parameters or pagination behavior are described; catalog is documented as an array.
- The API reference specifies idempotency behavior but does not document key storage scope beyond account association/order binding, nor a concurrency/locking guarantee for simultaneous requests using one key. Treat only the explicit no-double-charge retry promise as guaranteed; do not infer broader concurrency semantics.
- No general rate-limit SLA, exact IP burst/window, or retry guarantee for arbitrary non-order requests is stated. Sample retry guidance is implementation advice, not a guarantee that every 5xx means an order was or was not created; same-key retry is specifically recommended for orders.
- API docs do not define numeric precision/rounding for order price fields beyond balance precision notes, nor a currency conversion mechanism. All stated prices and balances are USDT.
