# Taste — UI / presentation

- Prefers compact list layouts with no wasted whitespace: entries should sit close together in a tight, scannable block ("jangan dibuat space terlalu lebar"), but with a small deliberate gap so they are not fully glued together ("berdempet tapi jangan terlalu dempet") — wide, airy spacing between rows reads as a defect. Confidence: 0.7
- Expects unavailable/sold-out items to be visually and functionally unambiguous: the action button turns red and is not clickable, and the "Sold out" label is paired with a red icon (e.g. a red ✕) right next to the text. Confidence: 0.7
- Drives UI review by pasting the current rendered output (e.g. the Telegram message text as the user sees it) and asking for a redesign with the desired state described in prose, rather than pointing at code or naming components. Confidence: 0.55
- Treats buyer-facing copy as his to proofread: before changes, he asks for the exact message-by-message experience the user gets ("pesan apa yang muncul setelah saya klik ... biar saya koreksi jika salah") and expects the agent to reconstruct the real strings verbatim — each screen's text plus the button labels and follow-up prompts, sourced from the actual renderer and locale files, not a paraphrase or a code summary — so he can correct the wording himself. Confidence: 0.5
- Wants visual consistency across screens: an existing presentation treatment should be reused for equivalent content elsewhere, pointed out by naming the reference treatment ("di bungkus quote sama seperti product details") rather than describing the styling from scratch. Confidence: 0.5
- Treats consistency itself as a standalone, worth-doing task — he greenlights it in one terse line ("oke silahkan buat konsistensi. lalu comit push.") and expects the canonical treatment to win everywhere, including the channel/post copy vocabulary (one emoji per concept, e.g. 📦 for stock in both the restock and sold-out posts) and locale files that drifted from the en/id wording. Cosmetic unification is not "nice to have" for him; it ships with the same commit/push + tests close as functional work. Confidence: 0.55
- Sets explicit, numeric minimums for paginated lists instead of leaving page size to the implementer (product list pages must show at least 15 items). Confidence: 0.55
- Treats catalog/list length as a UX constraint alongside spacing: he is wary of a design that makes the product list longer down the screen ("yang saya takutkan kalau hanya 1 variant dia bakalan panjang list produk kebawah") and prefers each entry to stay one compact line rather than a single item breaking into a multi-line block — surface list-length growth as a cost when proposing a change. Confidence: 0.5
- Wants Telegram message/caption copy annotated with emojis for visual appeal ("ada beberapa emote biar enak di pandang"), and frames it as consistency rather than decoration — a plain block of label:value lines reads as unfinished. Confidence: 0.55
- Likes buyer-facing copy to carry a scarcity/stock signal (telling the customer how much stock is left) as part of making the post appealing — states it as his own design plan and expects the agent to weigh it rather than silently drop it; he keeps pursuing the idea even after the agent argues against it ("kira kira misalnya kita tambahin 1 lagi yaitu sisa stock produk itu jadinya gimana?"), so treat it as an open design question to render and re-argue rather than a dismissed one. Confidence: 0.55
- Keeps public buyer-facing copy compact by dropping internal/administrative detail rather than explaining it: told to either shorten the provider/admin fee reference or remove it entirely, he chose "no need to be told at all" — the difference between subtotal and amount paid is left implicit in the caption because the attached invoice image already itemizes the fee. Confidence: 0.55
- Points at a live external website as the styling/motion benchmark instead of specifying the effect himself ("tambahkan sedikit animasi sama seperti website marketku.id"): the named site is the source of truth for the visual language, so expect the agent to study its actual CSS/keyframes/hover rules and translate that motion vocabulary into the existing storefront rather than inventing generic animations. The ask is framed as incremental polish ("sedikit"), so ramp up the existing UI with subtle motion rather than rebuilding the design. Confidence: 0.5
- Accepted the scarcity signal as a conditional, low-stock-only line (a "🔥 Only N left in stock" style hint rendered only while a few units remain, and silent at zero or for multi-item posts) rather than a permanent stock number burned into the frozen caption — after seeing that rendering he greenlit the narrower version for implementation. Confidence: 0.6
