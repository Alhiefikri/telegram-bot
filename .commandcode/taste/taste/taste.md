# Taste
- Follows a complete end-of-task loop for verified fixes: commit the change, push to the main branch, then close the related issue (with a summary comment) — all in one go, without waiting for a separate reminder to close the issue. Explicitly prompts the agent to do this when ready, repeating the instruction even if the work already finished ("silahkan commit dan push lalu close issue terkait", "oke silahkan commit dan close issue terkait") and expects the agent to verify state and report back if nothing is left. Confidence: 0.9
- Keeps production deployment out of the routine task loop: commit/push only trigger CI, and deploy stays an explicit manual dispatch ("jangan deploy") — but when the user does ask for it, the redeploy is the closing step of the loop ("...dan redeploy kembali"). Confidence: 0.7
- Wants a red CI/CD pipeline driven to green autonomously in one session: diagnose the failure, fix the root cause, verify the CI-equivalent checks locally, commit/push, re-run the pipeline until it passes, then redeploy and confirm the live release matches — without pausing for confirmation between steps ("jalankan workflow ci/cd looping sampai selesai fix jika ada masalah dan redeploy kembali"). Confidence: 0.8
- Expects the fix pass to clear every blocker, not just the first failure: latent issues that would break the next CI job (e.g. formatter/style violations hiding behind an earlier failing step) get fixed in the same pass so CI can go green in one push. Confidence: 0.55
- Communicates in Bahasa Indonesia (Indonesian); expects the agent to respond in Indonesian as well. Confidence: 0.9
- Steers sessions with terse prompts ("oke silahkan commit dan push lalu close issue terkait", "/cmd -yolo", "resume", "continue") and expects the agent to work autonomously through the full task loop without intermediate check-ins. Confidence: 0.65
- When asked to explain an issue ("masalahnya apa sih, coba jelasin", "jelasin ke saya kenapa itu terjadi dan apa perbaikan kamu"), prefers a plain-language walkthrough — root cause first, then the consequences (with concrete real-world impact), then the fix — using short, structured sections and avoiding jargon, rather than a purely technical changelog recap. Confidence: 0.6
- Treats verification as part of the task, not optional: before committing, run the whole test suite (`php artisan test`), the formatter in check mode (`./vendor/bin/pint --test`), and the heavyweight PostgreSQL concurrency gate (`composer test:concurrency-gate`) — each configured via env vars/artefact dirs — and report the pass counts as evidence. Confidence: 0.7
- Keeps a documented domain model: introducing a new domain concept means updating the `CONTEXT.md` glossary (including an "_Avoid_:" list of rejected synonyms), the `docs/agents/codebase.md` map/table/test index, and adding a numbered ADR under `docs/adr/`. Confidence: 0.65
- Treats production data remediation as part of a fix when the affected rows came from his own prod testing rather than real users: he authorises deleting the impacted production records outright ("biar yang udah pernah hit gapapa di hapusin aja, soalnya ini baru saya test di prod") alongside the code change. Confidence: 0.55
- Commit style: conventional-commit subject with the issue number in parentheses, a body explaining each decision group, an explicit "Evidence:" section with the test/formatting run results, and a `Co-authored-by:` trailer. Confidence: 0.6
- Aligns a new feature with the already-established equivalent flow instead of inventing a parallel custom mechanism: when something is "manual" it should behave like the existing manual purchase habit (customer sends a photo with the `/payment` caption and the operator reviews the forwarded proof). He states this expectation directly ("harusnya ... seperti di beli produk pada umummnya ... muncul di saya seperti membeli produk"). Confidence: 0.7
- Keeps the manual/automatic split by design: manual provider flows require the customer's payment proof forwarded to the admin for an approve/reject decision, while automatic providers (KlikQRIS, Sakurupiah) must credit on their own with no operator step — the manual copy must only appear on manual rails. Confidence: 0.65
- Scopes the agent to what was asked and keeps testing local-first: seeing long unrequested side work — public tunnel (ngrok), webhook re-pointing, Docker/disk cleanup, image rebuilds — reads as the agent going off-track, and he will stop it ("ini lu ngapain sih? kan saya mau test di local aja dulu?"). Expand beyond the requested step only after checking with him. Confidence: 0.65
